## 1. Advanced Agent Architecture and Orchestration (17%)
## 1. Kiến trúc agent nâng cao và điều phối (17%)

**What this domain tests.** You are given a production agent system (multi-agent, long-running, or near its context limit) and must choose the pattern, state mechanism, or context policy that fixes a stated cost, reliability, or quality problem. Distractors usually sound modular or "safer" but ignore context isolation, cache cost, or enforcement.
**Domain này kiểm tra gì.** Đề đưa ra một hệ thống agent production (đa agent, chạy dài, hoặc sắp chạm giới hạn context) và bạn phải chọn pattern, cơ chế lưu trạng thái hoặc chính sách context để giải quyết vấn đề về chi phí, độ tin cậy hay chất lượng. Đáp án nhiễu thường nghe "module hóa" hoặc "an toàn hơn" nhưng bỏ qua cô lập context, chi phí cache hoặc việc cưỡng chế thực sự.

### [1.1] Multi-Agent Orchestration
### [1.1] Điều phối đa agent

- **Core idea:** Orchestrator-worker (supervisor/worker): a lead agent plans, delegates to subagents, and synthesizes. In Anthropic's research system a lead agent (Opus 4) runs parallel subagents (Sonnet 4) plus a separate CitationAgent; subagents act as filters that search iteratively and return condensed findings.
- **Ý chính:** Orchestrator-worker (supervisor/worker): agent chủ lập kế hoạch, giao việc cho subagent rồi tổng hợp. Trong hệ thống research của Anthropic, lead (Opus 4) chạy các subagent song song (Sonnet 4) cộng thêm một CitationAgent riêng; subagent đóng vai bộ lọc, tìm kiếm lặp rồi trả về kết quả đã cô đọng.
- **Core idea:** Context isolation: in the Agent SDK a non-fork subagent starts fresh. The only parent-to-child channel is the Agent tool's prompt string, and only the subagent's final message returns. So the parent must write file paths, errors, and decisions into that prompt. Example: "fix the bug" fails; "fix the null check in /src/auth.ts, error X, we already ruled out Y" works.
- **Ý chính:** Cô lập ngữ cảnh: trong Agent SDK, subagent (không phải fork) bắt đầu với context mới. Kênh duy nhất từ cha sang con là chuỗi prompt của Agent tool, và chỉ tin nhắn cuối của subagent quay về cha. Vì vậy cha phải ghi đường dẫn file, lỗi, quyết định vào prompt. Ví dụ: "sửa bug" thất bại; "sửa null check ở /src/auth.ts, lỗi X, đã loại trừ Y" thì chạy được.
- **Core idea:** Communication options: the Agent tool's return value, `SendMessage` between named agents, and Managed Agents session threads (isolated event streams, shared sandbox/filesystem). To avoid the "telephone game" with large outputs, subagents write to external storage and pass a lightweight reference.
- **Ý chính:** Các kênh giao tiếp: giá trị trả về của Agent tool, `SendMessage` giữa agent có tên, và session threads của Managed Agents (event stream cô lập nhưng chung sandbox/filesystem). Để tránh "telephone game" với output lớn, subagent ghi ra kho ngoài và chỉ truyền tham chiếu nhẹ.
- **Core idea:** Multi-agent pays off for context pollution, independent parallelizable work, or specialization (15-20+ tools). Decompose by context boundary, not by job type; planner/implementer/tester/reviewer splits burned tokens on coordination. Parallel work finishes in the time of the slowest task, but total tokens rise 3-10x.
- **Ý chính:** Đa agent có lợi khi context bị nhiễu, việc độc lập có thể song song, hoặc cần chuyên môn hóa (15-20+ tool). Chia theo ranh giới context, không chia theo loại việc; kiểu planner/implementer/tester/reviewer tốn token cho điều phối. Việc song song xong trong thời gian của tác vụ chậm nhất, nhưng tổng token tăng 3-10 lần.
- **Core idea:** Human-in-the-loop: SDK `canUseTool` fires for tool approval and `AskUserQuestion`, pausing execution until it returns allow, deny (message visible to Claude), allow with `updatedInput`, or approve-and-remember via `updatedPermissions`. Managed Agents use the `always_ask` policy: the session goes `idle` with `requires_action`, and you answer with `user.tool_confirmation`.
- **Ý chính:** Human-in-the-loop: `canUseTool` của SDK kích hoạt khi cần duyệt tool và với `AskUserQuestion`, tạm dừng thực thi đến khi trả về allow, deny (Claude thấy thông điệp), allow kèm `updatedInput`, hoặc "duyệt và nhớ" qua `updatedPermissions`. Managed Agents dùng policy `always_ask`: session chuyển `idle` với `requires_action`, bạn trả lời bằng `user.tool_confirmation`.
- **Must-know facts:** Research system beat single-agent Opus 4 by 90.2% on its internal eval; multi-agent ~15x chat tokens (agents ~4x); token usage alone explained 80% of BrowseComp variance (Doc). Lead launches 3-5 subagents in parallel, each using 3+ tools in parallel, cutting research time up to 90% (Doc). Effort scaling: simple fact-find = 1 agent/3-10 calls; comparison = 2-4 subagents; complex = >10 subagents (Doc). `AgentDefinition` requires `description` and `prompt`; optional `tools`, `disallowedTools`, `model`, `skills`, `memory`, `mcpServers`, `maxTurns`, `background`, `effort`, `permissionMode`; subagents are invoked via the `Agent` tool (shows as `Task` in `system:init`) (Doc). Subagent gets its own prompt, the Agent tool prompt string, project CLAUDE.md and tool definitions, but not parent history, parent system prompt, or unlisted skills (Doc). Caps: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` default 3; `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` default 20; `maxBudgetUsd` triggers `error_max_budget_usd` (Doc). `AskUserQuestion` is unavailable inside subagents; 1-4 questions with 2-4 options each (Doc). Managed Agents: delegation one level deep, max 25 child threads; permission policies `always_allow`/`always_ask`/`auto`, MCP toolsets default to `always_ask` (Doc). Listing a tool in `tools` does not pre-approve it (Doc). Policy evaluation order: deny rules, permission mode, allow rules run before `canUseTool` (Doc).
- **Kiến thức phải nhớ:** Research system hơn single-agent Opus 4 90,2% trên eval nội bộ; multi-agent ~15x token so với chat (agent đơn ~4x); riêng lượng token giải thích 80% phương sai BrowseComp (Doc). Lead chạy 3-5 subagent song song, mỗi subagent dùng 3+ tool song song, giảm thời gian research tới 90% (Doc). Scale theo độ khó: tra cứu đơn giản = 1 agent/3-10 lần gọi; so sánh = 2-4 subagent; phức tạp = >10 subagent (Doc). `AgentDefinition` bắt buộc `description` và `prompt`; tùy chọn `tools`, `disallowedTools`, `model`, `skills`, `memory`, `mcpServers`, `maxTurns`, `background`, `effort`, `permissionMode`; subagent gọi qua `Agent` tool (hiện là `Task` trong `system:init`) (Doc). Subagent nhận prompt riêng, chuỗi prompt của Agent tool, CLAUDE.md của project và định nghĩa tool, nhưng không nhận lịch sử cha, system prompt cha hay skill không được liệt kê (Doc). Giới hạn: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` mặc định 3; `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` mặc định 20; `maxBudgetUsd` gây `error_max_budget_usd` (Doc). `AskUserQuestion` không dùng được trong subagent; 1-4 câu hỏi, mỗi câu 2-4 lựa chọn (Doc). Managed Agents: ủy quyền sâu một cấp, tối đa 25 child thread; policy `always_allow`/`always_ask`/`auto`, MCP toolset mặc định `always_ask` (Doc). Liệt kê tool trong `tools` không có nghĩa là đã pre-approve (Doc). Thứ tự đánh giá: deny rules, permission mode, allow rules chạy trước `canUseTool` (Doc).
- **Decision rule:** When subtasks are independent, large, and read-heavy (research, multi-file audit) → orchestrator plus parallel subagents because each gets clean context and returns a summary; when work is tightly coupled (one repo, feature plus its tests) → keep ONE agent. Trap: role-based splits (planner/coder/tester/reviewer) look modular but waste tokens and lose context at handoffs. Also: for runaway spawning set depth/concurrency caps and `max_budget_usd`; prompt-only "don't spawn too many" is not enforcement. For risky tool calls use `canUseTool`/`PreToolUse` or `always_ask`, not `allowedTools` (which pre-approves).
- **Quy tắc quyết định:** Khi các subtask độc lập, lớn, nặng đọc (research, audit nhiều file) → chọn orchestrator cùng subagent song song vì mỗi subagent có context sạch và trả về bản tóm tắt; khi việc gắn chặt (một repo, feature và test của nó) → giữ MỘT agent. Bẫy: chia theo vai (planner/coder/tester/reviewer) nghe module hóa nhưng tốn token và mất context ở các điểm bàn giao. Ngoài ra: chống spawn tràn lan bằng giới hạn depth/concurrency và `max_budget_usd`; chỉ dặn trong prompt không phải cưỡng chế. Tool rủi ro dùng `canUseTool`/`PreToolUse` hoặc `always_ask`, không dùng `allowedTools` (nó pre-approve).

### [1.2] Durable Execution and State Management
### [1.2] Thực thi bền vững và quản lý trạng thái

- **Core idea:** SDK sessions persist the conversation, not the filesystem, as JSONL under `~/.claude/projects/<encoded-cwd>/`. `continue` = latest session in cwd; `resume` = by session ID; `fork` = new session with copied history, original untouched.
- **Ý chính:** Session của SDK lưu hội thoại, không lưu filesystem, dưới dạng JSONL trong `~/.claude/projects/<encoded-cwd>/`. `continue` = session gần nhất trong cwd; `resume` = theo session ID; `fork` = session mới với bản sao lịch sử, bản gốc giữ nguyên.
- **Core idea:** Checkpointing has three layers: conversation (transcript), files (SDK file checkpointing, rewind to a user-message UUID), and project state (git commits plus a progress file for multi-session work). File checkpointing does not undo Bash edits or subagent edits, and does not rewind the conversation.
- **Ý chính:** Checkpoint có ba lớp: hội thoại (transcript), file (file checkpointing của SDK, rewind tới UUID của user message), và trạng thái project (git commit cộng file progress cho việc nhiều session). File checkpointing không hoàn tác thay đổi qua Bash hay subagent, và không rewind hội thoại.
- **Core idea:** Cross-host resume: transcripts are local, so a `SessionStore` adapter (`append` and `load` required) mirrors them to S3/Redis/Postgres, and the new host resumes from a matching cwd. Managed Agents instead hosts the session server-side (history, sandbox state, outputs), so it resumes cleanly after pauses.
- **Ý chính:** Resume giữa nhiều host: transcript nằm local nên cần adapter `SessionStore` (bắt buộc `append` và `load`) để mirror sang S3/Redis/Postgres, host mới resume từ cwd khớp. Managed Agents thì lưu session phía server (lịch sử, trạng thái sandbox, output) nên resume gọn sau khi tạm dừng.
- **Core idea:** Long-running harness pattern: an initializer agent writes `init.sh`, `claude-progress.txt`, a JSON feature list (200+ features, only the `passes` boolean editable) and the first git commit. Each later session reads git log and progress, picks one feature, smoke-tests end to end, works, commits. JSON is used because models overwrite it less than Markdown.
- **Ý chính:** Pattern harness chạy dài: initializer agent viết `init.sh`, `claude-progress.txt`, danh sách feature JSON (200+ feature, chỉ sửa được boolean `passes`) và git commit đầu tiên. Mỗi session sau đọc git log và progress, chọn một feature, smoke test end-to-end, làm, rồi commit. Dùng JSON vì model ít ghi đè hơn Markdown.
- **Must-know facts:** `persistSession: false` is TypeScript only and conflicts with a store (SDK throws) (Doc). `SessionStore`: optional `listSessions`, `listSessionSummaries`, `delete`, `listSubkeys`; dual-write (local first); `append` retried up to 3 attempts total, deduped by `entry.uuid`; failure emits `mirror_error` (Doc). File checkpointing needs `enableFileCheckpointing` plus the `replay-user-messages` extra arg; same-session only (Doc). Managed Agents beta header `managed-agents-2026-04-01`; not ZDR/HIPAA eligible; statuses `idle`/`running`/`rescheduling`/`terminated` (Doc). Only `tools` and `mcp_servers` can change after session creation (and the session must be `idle`); `system` and `model` are fixed for the session lifetime (Doc). `agent_with_overrides` replaces model/system/tools for one session; `initial_events` max 50; `budget.max_list_cost` in cents leads to `budget_reached` (Doc). A `PreToolUse` hook `defer` decision lets the process exit and resume later from the persisted session; its mechanism details were not read (Unverified). Whether an existing SDK transcript can resume on a different model is not stated (Unverified). With preserved thinking, reinserted earlier thinking blocks fail the prefix check after compaction; strip them or set `prefix_mismatch_behavior: "drop_block"` (Doc).
- **Kiến thức phải nhớ:** `persistSession: false` chỉ có ở TypeScript và xung đột với store (SDK báo lỗi) (Doc). `SessionStore`: tùy chọn `listSessions`, `listSessionSummaries`, `delete`, `listSubkeys`; dual-write (local trước); `append` thử lại tối đa 3 lần tổng cộng, khử trùng theo `entry.uuid`; lỗi phát ra `mirror_error` (Doc). File checkpointing cần `enableFileCheckpointing` cộng extra arg `replay-user-messages`; chỉ trong cùng session (Doc). Managed Agents dùng beta header `managed-agents-2026-04-01`; không đủ điều kiện ZDR/HIPAA; trạng thái `idle`/`running`/`rescheduling`/`terminated` (Doc). Sau khi tạo session chỉ đổi được `tools` và `mcp_servers` (và session phải `idle`); `system` và `model` cố định suốt vòng đời session (Doc). `agent_with_overrides` thay model/system/tools cho một session; `initial_events` tối đa 50; `budget.max_list_cost` tính bằng cent dẫn tới `budget_reached` (Doc). Quyết định `defer` của hook `PreToolUse` cho phép process thoát rồi resume sau từ session đã lưu; chi tiết cơ chế chưa đọc (Unverified). Transcript SDK có resume được trên model khác hay không thì tài liệu không nêu (Unverified). Với preserved thinking, thinking block cũ chèn lại sẽ lỗi prefix check sau compaction; hãy bỏ chúng hoặc đặt `prefix_mismatch_behavior: "drop_block"` (Doc).
- **Decision rule:** When approval may take hours or days → `defer` via PreToolUse hook (SDK) or Managed Agents `idle` + `requires_action` because the process need not stay alive. Trap: a pending `canUseTool` callback works but pins the process. When a worker restarts or moves host → `SessionStore` plus resume from matching cwd. Trap: assuming session files are cluster-shared or that sessions snapshot the filesystem. When bad file edits must be undone → file checkpointing, but use git for Bash/subagent edits. When a multi-session project declares "done" early → initializer + coding-agent pattern with `passes` only after e2e verification. When a model upgrade is coming → keep durable state in memory/progress files/git, pin agent versions, roll out via new sessions (Interp).
- **Quy tắc quyết định:** Khi việc duyệt có thể mất hàng giờ/ngày → dùng `defer` qua PreToolUse hook (SDK) hoặc `idle` + `requires_action` của Managed Agents vì process không cần sống liên tục. Bẫy: callback `canUseTool` treo vẫn chạy nhưng giữ process. Khi worker restart hoặc chuyển host → `SessionStore` cộng resume từ cwd khớp. Bẫy: tưởng file session dùng chung trong cluster hoặc session chụp snapshot filesystem. Khi cần hoàn tác sửa file hỏng → file checkpointing, nhưng thay đổi qua Bash/subagent phải dùng git. Khi project nhiều session cứ báo "xong" sớm → initializer + coding-agent, chỉ đặt `passes` sau khi verify e2e. Khi sắp nâng cấp model → giữ trạng thái bền trong memory/progress/git, pin phiên bản agent, triển khai bằng session mới (Interp).

### [1.3] Architecture Selection at Scale
### [1.3] Chọn kiến trúc ở quy mô lớn

- **Core idea:** A workflow is LLM plus tools orchestrated by predefined code paths; an agent directs its own process and tool use. The five workflow patterns are prompt chaining, routing, parallelization (sectioning/voting), orchestrator-workers, evaluator-optimizer.
- **Ý chính:** Workflow là LLM cùng tool được điều phối bằng đường code định sẵn; agent tự định hướng quy trình và việc dùng tool. Năm pattern workflow: prompt chaining, routing, parallelization (sectioning/voting), orchestrator-workers, evaluator-optimizer.
- **Core idea:** Use the simplest thing that works and add complexity only when it demonstrably improves outcomes. Workflows suit predictable tasks; agents suit open-ended tasks with unknown step counts, at the price of cost, latency, and compounding error.
- **Ý chính:** Dùng thứ đơn giản nhất chạy được, chỉ thêm độ phức tạp khi nó cải thiện kết quả một cách rõ ràng. Workflow hợp với tác vụ dự đoán được; agent hợp với tác vụ mở, số bước không biết trước, đổi lại chi phí, độ trễ và lỗi cộng dồn.
- **Core idea:** Evolving a running system means using cost, reliability, and quality data (eval scores, token use, failure cohorts) to harden a stable agentic step into a workflow, or add an agentic fallback where a workflow fails on long-tail inputs (Interp).
- **Ý chính:** Tiến hóa hệ thống đang chạy nghĩa là dùng dữ liệu chi phí, độ tin cậy, chất lượng (điểm eval, lượng token, nhóm lỗi) để "đóng cứng" bước agentic ổn định thành workflow, hoặc thêm fallback agentic ở chỗ workflow hỏng với input đuôi dài (Interp).
- **Core idea:** Harness choice runs from raw Messages API loop (max control) to Agent SDK (Claude Code's loop, sessions, subagents, hooks) to Managed Agents (hosted harness plus sandbox, suited to long-running asynchronous work). Frameworks can hide prompts and responses and hamper debugging.
- **Ý chính:** Lựa chọn harness trải từ vòng lặp Messages API thô (kiểm soát tối đa), tới Agent SDK (vòng lặp của Claude Code, session, subagent, hook), tới Managed Agents (harness host sẵn cùng sandbox, hợp việc chạy dài và bất đồng bộ). Framework có thể che prompt/response và gây khó debug.
- **Must-know facts:** Multi-agent typically uses 3-10x tokens vs a single agent; documented failure modes include lost context at handoffs, problem-type splits, tightly coupled components, misrouting, and verifier "early victory" (Doc). Managed Agents is "best for long-running and asynchronous work" (Doc). Reusable subagent definitions (`AgentDefinition`, `.claude/agents/`), Skills, and shared MCP servers are standardization vehicles (Interp). A verifier subagent needs concrete criteria and negative tests (Doc).
- **Kiến thức phải nhớ:** Multi-agent thường dùng 3-10 lần token so với agent đơn; các failure mode có tài liệu gồm mất context khi bàn giao, chia theo loại vấn đề, thành phần gắn chặt, misrouting và verifier "early victory" (Doc). Managed Agents "phù hợp nhất cho việc chạy dài và bất đồng bộ" (Doc). Định nghĩa subagent tái sử dụng (`AgentDefinition`, `.claude/agents/`), Skills và MCP server dùng chung là phương tiện chuẩn hóa (Interp). Verifier subagent cần tiêu chí cụ thể và negative test (Doc).
- **Decision rule:** When steps are fixed and known and predictability matters → workflow (chaining/routing/parallelization); when the number of steps is unknown → agent. Choose Managed Agents for long-running async work with minimal infra, Agent SDK for programmatic control with hooks/sessions, raw API loop for fine-grained control. Trap: "always use a framework in production" (abstractions obscure prompts) and "multi-agent is always higher quality" (quality gains concentrate in breadth tasks at 3-15x tokens). Trap: Managed Agents for ZDR-bound workloads (not eligible).
- **Quy tắc quyết định:** Khi các bước cố định, đã biết và cần tính dự đoán được → workflow (chaining/routing/parallelization); khi số bước chưa biết → agent. Chọn Managed Agents cho việc chạy dài bất đồng bộ với hạ tầng tối thiểu, Agent SDK khi cần kiểm soát bằng code với hook/session, vòng lặp API thô khi cần kiểm soát chi tiết. Bẫy: "production luôn nên dùng framework" (abstraction che prompt) và "multi-agent luôn chất lượng hơn" (chất lượng tăng chủ yếu ở tác vụ rộng, với 3-15 lần token). Bẫy: dùng Managed Agents cho workload bắt buộc ZDR (không đủ điều kiện).

### [1.4] Context and Memory Architecture
### [1.4] Kiến trúc context và bộ nhớ

- **Core idea:** Context rot: recall accuracy falls as the window fills, so every token must earn its place. The toolbox from lightest to heaviest: tool-result clearing, compaction, memory tool/notes, subagents (return 1,000-2,000-token summaries), tool search, and cache-safe instruction changes.
- **Ý chính:** Context rot: độ chính xác recall giảm khi cửa sổ đầy, nên mỗi token phải xứng đáng. Bộ công cụ từ nhẹ đến nặng: xóa tool result, compaction, memory tool/ghi chú, subagent (trả về bản tóm tắt 1.000-2.000 token), tool search, và thay đổi chỉ dẫn an toàn với cache.
- **Core idea:** Choose by what is bloating the window. Clearing removes old tool results server-side by rule (client keeps full history). Compaction replaces older turns with a summary and is the primary strategy when conversational flow matters. The memory tool persists facts outside context so they survive both.
- **Ý chính:** Chọn theo thứ đang làm phình cửa sổ. Clearing xóa tool result cũ phía server theo luật (client giữ đủ lịch sử). Compaction thay các lượt cũ bằng bản tóm tắt và là chiến lược chính khi mạch hội thoại quan trọng. Memory tool lưu sự kiện ngoài context để sống sót qua cả hai.
- **Core idea:** Prompt cache order is tools, then system, then messages; a change invalidates that level and everything after. Editing `system` or tool definitions mid-conversation therefore forfeits the cache, whereas appending a system-role message keeps the prefix intact.
- **Ý chính:** Thứ tự prompt cache là tools, rồi system, rồi messages; thay đổi một tầng làm mất hiệu lực tầng đó và mọi tầng sau. Sửa `system` hay định nghĩa tool giữa hội thoại sẽ mất cache, còn append một message role system thì giữ nguyên prefix.
- **Core idea:** Tool search keeps huge catalogs out of the window: mark tools `defer_loading: true` and the model discovers them on demand, which also helps selection accuracy that degrades beyond 30-50 tools.
- **Ý chính:** Tool search giữ catalog khổng lồ ngoài cửa sổ: đánh dấu tool `defer_loading: true` để model tìm khi cần, đồng thời cải thiện độ chính xác chọn tool vốn giảm khi vượt 30-50 tool.
- **Must-know facts:** Context editing beta `context-management-2025-06-27`; strategies `clear_tool_uses_20250919` and `clear_thinking_20251015`; `clear_tool_uses` params `trigger` (default 100,000 input tokens), `keep` (default 3), `clear_at_least`, `exclude_tools`, `clear_tool_inputs` (default false); response shows `context_management.applied_edits` (Doc). Clearing invalidates the cached prefix, so use `clear_at_least` (Doc). `clear_thinking` keeps last 1 thinking turn by default; put it first when combined (Doc). Compaction: on-demand beta `compact-2026-09-04` with top-level `compaction` parameter; threshold beta `compact-2026-01-12`, type `compact_20260112`; `trigger` default 150,000, minimum 50,000; `pause_after_compaction` yields `stop_reason: "compaction"`; `instructions` REPLACES the default summary prompt; bill by summing `usage.iterations` (Doc). Memory tool: type `memory_20250818`, CLIENT-side, commands `view`/`create`/`str_replace`/`insert`/`delete`/`rename` under `/memories`; must block path traversal; ZDR eligible; no beta header (Doc). Tool search: `tool_search_tool_regex_20251119` (pattern max 200 chars) and `tool_search_tool_bm25_20251119` (max 500); at least one tool non-deferred; up to 10,000 deferred tools; 5 matches by default; ~55k-token setup cut over 85%; use at 10+ tools or >10k tokens of definitions; keep 3-5 hot tools loaded; deferred tool with `cache_control` returns 400 (Doc). Tool search not available in Managed Agents per its page (Doc). Cache: TTL 5 min default (write 1.25x) or 1 h (2x); read 0.1x; 20-block lookback (Doc). Mid-conversation system-role message supported on listed models, not Claude Sonnet 5; tool additions via beta `inline-tools-2026-09-15` `tool_addition` block (Doc).
- **Kiến thức phải nhớ:** Context editing beta `context-management-2025-06-27`; chiến lược `clear_tool_uses_20250919` và `clear_thinking_20251015`; tham số `clear_tool_uses`: `trigger` (mặc định 100.000 input token), `keep` (mặc định 3), `clear_at_least`, `exclude_tools`, `clear_tool_inputs` (mặc định false); response có `context_management.applied_edits` (Doc). Clearing làm mất hiệu lực prefix đã cache nên dùng `clear_at_least` (Doc). `clear_thinking` mặc định giữ 1 lượt thinking cuối; đặt nó đầu tiên khi kết hợp (Doc). Compaction: on-demand beta `compact-2026-09-04` với tham số top-level `compaction`; theo ngưỡng beta `compact-2026-01-12`, type `compact_20260112`; `trigger` mặc định 150.000, tối thiểu 50.000; `pause_after_compaction` cho `stop_reason: "compaction"`; `instructions` THAY THẾ prompt tóm tắt mặc định; tính phí bằng cách cộng `usage.iterations` (Doc). Memory tool: type `memory_20250818`, phía CLIENT, lệnh `view`/`create`/`str_replace`/`insert`/`delete`/`rename` dưới `/memories`; phải chặn path traversal; đủ điều kiện ZDR; không cần beta header (Doc). Tool search: `tool_search_tool_regex_20251119` (pattern tối đa 200 ký tự) và `tool_search_tool_bm25_20251119` (tối đa 500); ít nhất một tool không deferred; tới 10.000 tool deferred; mặc định trả 5 kết quả; setup ~55k token giảm hơn 85%; dùng khi 10+ tool hoặc >10k token định nghĩa; giữ 3-5 tool "nóng"; tool deferred có `cache_control` trả 400 (Doc). Tool search không có trong Managed Agents theo trang của nó (Doc). Cache: TTL mặc định 5 phút (ghi 1,25x) hoặc 1 giờ (2x); đọc 0,1x; lookback 20 block (Doc). Message role system giữa hội thoại hỗ trợ trên các model được liệt kê, không phải Claude Sonnet 5; thêm tool qua beta `inline-tools-2026-09-15` block `tool_addition` (Doc).
- **Decision rule:** When the context nears its limit and flow matters → compaction; when it is mostly stale tool results (searches, file reads) → `clear_tool_uses` with `exclude_tools` and `clear_at_least`; when facts must survive either → memory tool. When instructions must change mid-conversation without a cache miss → append a system-role message (or inline tool addition) because the prefix stays untouched. When 50+ tools hurt selection → tool search with `defer_loading`. Traps: compaction `instructions` do not add to the default, they replace it; compaction trigger below 50,000 is invalid; deferring ALL tools (400); removing definitions from `tools` (still required); editing `system` or tool definitions to change behaviour (cache invalidated); "start a new conversation" (loses cached context); tool search for under 10 small tools (not worth it).
- **Quy tắc quyết định:** Khi context gần giới hạn và mạch hội thoại quan trọng → compaction; khi chủ yếu là tool result cũ (search, đọc file) → `clear_tool_uses` với `exclude_tools` và `clear_at_least`; khi sự kiện phải sống sót qua cả hai → memory tool. Khi cần đổi chỉ dẫn giữa hội thoại mà không bị cache miss → append message role system (hoặc thêm tool inline) vì prefix không bị đụng tới. Khi 50+ tool làm giảm độ chính xác chọn → tool search với `defer_loading`. Bẫy: `instructions` của compaction không cộng thêm vào mặc định mà thay thế nó; trigger compaction dưới 50.000 không hợp lệ; defer TẤT CẢ tool (lỗi 400); bỏ định nghĩa khỏi `tools` (vẫn bắt buộc); sửa `system` hoặc định nghĩa tool để đổi hành vi (mất cache); "mở hội thoại mới" (mất context đã cache); dùng tool search cho dưới 10 tool nhỏ (không đáng).

### Self-check / Tự kiểm tra

1. Q: What is the only parent-to-child channel for a fresh SDK subagent? A: The Agent tool's prompt string.
   Hỏi: Kênh duy nhất từ cha sang subagent mới của SDK là gì? Đáp: Chuỗi prompt của Agent tool.
2. Q: Why split multi-agent work by context boundary rather than by role? A: Role splits (planner/coder/tester/reviewer) burn tokens on coordination and lose context at handoffs.
   Hỏi: Vì sao chia đa agent theo ranh giới context thay vì theo vai? Đáp: Chia theo vai tốn token điều phối và mất context ở các điểm bàn giao.
3. Q: Default `trigger` for `clear_tool_uses`, and why set `clear_at_least`? A: 100,000 input tokens; each clear invalidates the cached prefix, so it must free enough tokens to be worth it.
   Hỏi: `trigger` mặc định của `clear_tool_uses` là bao nhiêu và vì sao đặt `clear_at_least`? Đáp: 100.000 input token; mỗi lần clear làm mất cache prefix nên phải giải phóng đủ token mới đáng.
4. Q: Minimum and default `trigger` for `compact_20260112`? A: Minimum 50,000; default 150,000.
   Hỏi: `trigger` tối thiểu và mặc định của `compact_20260112`? Đáp: Tối thiểu 50.000; mặc định 150.000.
5. Q: Does the memory tool run on Anthropic servers? A: No, it is client-side; your handler runs the commands on `/memories` and must block path traversal.
   Hỏi: Memory tool có chạy trên server Anthropic không? Đáp: Không, nó chạy phía client; handler của bạn thực thi lệnh trên `/memories` và phải chặn path traversal.
6. Q: How do you change instructions mid-conversation without a cache miss? A: Append a `role: "system"` message instead of editing `system` (not on Claude Sonnet 5).
   Hỏi: Đổi chỉ dẫn giữa hội thoại mà không cache miss bằng cách nào? Đáp: Append message `role: "system"` thay vì sửa `system` (không áp dụng cho Claude Sonnet 5).
7. Q: A Managed Agents session pauses on an `always_ask` tool; what do you receive and send? A: `session.status_idle` with `requires_action`; send `user.tool_confirmation` (allow/deny).
   Hỏi: Session Managed Agents dừng ở tool `always_ask`; nhận gì và gửi gì? Đáp: Nhận `session.status_idle` với `requires_action`; gửi `user.tool_confirmation` (allow/deny).
8. Q: What does SDK file checkpointing NOT undo? A: Bash-made file changes, subagent edits, and the conversation itself.
   Hỏi: File checkpointing của SDK KHÔNG hoàn tác điều gì? Đáp: Thay đổi file qua Bash, chỉnh sửa của subagent và chính hội thoại.
