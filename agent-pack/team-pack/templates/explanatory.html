Mock Q1You are comparing patterns for a batch document-classification job that follows fixed steps: extract metadata, classify, summarize, and persist. Which pattern is the best fit and why?
  • A. A workflow pattern, because the steps are well-defined and predictable per-request token cost is preferred over flexibility.
  • B. An agentic pattern, because agents tend to be more accurate than workflows, so this is a reasonable default choice for most classification tasks.
  • C. An agentic pattern, because the open-ended planning capability of agents produces more consistent structured outputs than a fixed workflow graph on classification tasks.
  • D. A workflow pattern, because agentic patterns generally cost more per request than a workflow graph, regardless of the task's structure.

❌ Why your choice loses

✅ Why the winning answer wins

Because every step is known in advance, a predefined code path gives bounded per-request cost and auditable, retryable stages. The pattern is chosen from the task's structure, not from blanket claims about agents being more accurate or always more expensive.

🧠 Exam Pattern

Fixed, known steps → workflow for predictable cost and auditability

Key signals: batch document-classification job; follows fixed steps; extract, classify, summarize, persist

📝 Full explanation

The steps are fixed and known in advance, so a workflow (predefined code path) fits: per-request cost is predictable and each stage can be audited and retried. Agents are not inherently more accurate or consistent (B, C). D picks the right pattern for the wrong reason: the choice should follow the task's structure, not a blanket cost rule.

Each correct answer presents part of the solution. Select 2

  • B. Have subagents return condensed findings to the lead agent rather than passing their full raw tool output into its context.
  • C. Replace the subagents with a single agent that runs every sub-question sequentially in one shared context.

  • E. Give every subagent the full tool set and the complete conversation history of the lead agent by default.

Duplication comes from vague delegation and flooding comes from raw returns. Scoped task briefs prevent overlap at the source, and condensed results keep the raw material isolated in each subagent's own context.

  5. Per-slice requirements need per-slice measurement; aggregates hide failures.
  6. Accuracy-neutral optimizations first: cache stable prefixes and repeated content.
  7. Stable content first, dynamic content last, so the prefix can be cached.
  8. Fixed, dependent steps -> workflow; open-ended steps -> agent.
  9. Decompose bloated agents by domain before adding routers or more models.
  10. Progressive discovery (tool search, Skills on demand) beats loading everything.
  11. Identity done right: per-user scoped tokens, secrets server-side, RBAC before retrieval.

  14. Layer guardrails (input, prompt, output, schema); temperature and logs are not guardrails.
  15. Choose the lightest model that meets the quality bar on a representative sample.
  16. Direct API for stateless calls, MCP for portability, agent-to-agent for stateful long tasks.
  17. Structure-aware chunking and retrieval matched to data shape and query pattern.
  18. Observability: correlation IDs, per-span tokens/latency, model version on every turn.
  19. Compliance needs contracts and configuration (BAA, ZDR, DPA, audit), not prompts.
  20. Fairness: agreement with humans and approval parity do not prove fairness.
  21. Lead with decision, outcome and trade-offs; tailor depth to each audience.
